# NFL Matchup Analytics & Spread Model

A Python pipeline that pulls free NFL data every week, builds an opponent-adjusted team rating, and generates a set of PDF matchup reports and spread picks from one command.

| | |
|---|---|
| **Language** | Python 3.9+ |
| **Libraries** | pandas, NumPy, reportlab, nflreadpy, requests (scikit-learn, streamlit and curl_cffi are optional) |
| **Data** | [nflverse](https://nflverse.com) (free, CC BY 4.0): play-by-play, team and player stats, injuries, schedules, betting lines |
| **Run it** | `python3 nfl_run_all.py` |

## What it does

Each week the pipeline refreshes the data, rebuilds every report, grades its own earlier picks against real results, and retrains. Everything is generated by code. The project has three parts: **descriptive matchup sheets** that show what each team has actually done, a **margin model** that predicts the score, and a **spread model** that predicts how a game finishes against the Vegas number.

## The reports it generates

| Report | What it shows |
|---|---|
| Full slate (about 80 pages) | A multi-page sheet for every game: VOID rating, net EPA, success rate, points per drive, rush and pass matchups, pressure and sack numbers, scheme tendencies and the injury report. Every game also gets its own PDF. |
| Quick-scan sheet (about 30 pages) | The trimmed, print-and-carry version of the same matchups. |
| Delta scan sheet (about 15 pages) | One page per game showing only the gaps between the two teams. Large gaps in VOID, success rate and points per drive are highlighted in teal. |
| League superlatives (12 pages) | Best and worst team in every category, top 3 and bottom 3, plus games where both teams sit at an extreme. |
| Workhorse tracker (about 18 pages) | Each team's lead back, top three pass-catchers and QB: workload, efficiency vs their own baseline, scoring without them and injury impact. Descriptive, not a pick. |
| Spread AI picks (2 pages) | Picks against the Vegas spread with model line, edge, projected score, season record against the number and the biggest drivers. |

## How a run works

| Step | Script | Output |
|---|---|---|
| 1 | `nfl_data_pull.py` | Fresh team, player, injury and game-log data (CSV); dated snapshots in `history/` |
| 2 | `nfl_matchup_sheet.py` (+ `nfl_delta_grid.py`, `nfl_margin_model.py`) | Full slate, quick-scan, per-game and delta-scan PDFs; logs the model's picks |
| 3 | `nfl_superlatives.py` | League Superlatives PDF |
| 4 | `nfl_workhorse_tracker.py` | Workhorse Tracker PDF |
| 5 | `nfl_spread_ai.py` | Spread picks PDF and CSV; grades earlier picks; retrains on every completed game |
| 6 | `nfl_model_scorecard.py` | Scores every logged pick whose game is final |

## Methods

### VOID (opponent-adjusted efficiency)
A DVOA-style rating built from public play-by-play: each team's efficiency adjusted for the quality of the opponents it faced, ranked 1 to 32. It exists because commercial equivalents are paywalled and cannot be redistributed.

### Margin model (`nfl_margin_model.py`)
- Implemented from scratch in NumPy: a 20-feature multivariate regression fit by least squares, predicting scoring margin and total.
- Walk-forward feature engineering: a team's stats going into a game use only games from strictly earlier weeks, so there is no leakage.
- A hand-written win-probability calibration that minimizes log-loss with a golden-section search.
- A holdout test: fit on prior seasons, then check the current season's completed games.

### Spread AI (`nfl_spread_ai.py`)
- **Target:** actual home margin minus the Vegas spread, so the model only learns what the market missed.
- **Inputs:** opponent-adjusted, exponentially weighted team ratings from play-by-play (EPA, success rate, pass and rush EPA, explosive plays, sacks, early downs, turnovers, points), carried across seasons; a shrunk quarterback rating with QB-change flags; rest, short week, bye, division, dome, wind and cold.
- **Models:** ridge regression, a small neural network written in NumPy (Adam, L2, input noise, early stopping) and, if scikit-learn is installed, gradient boosting. The blend is shrunk by its own out-of-sample slope.
- **Evaluation:** walk-forward backtest in 4-week blocks from 2018 onward; every game is predicted by a model that never saw it. Wilson confidence intervals and a significance test against the 52.38% break-even.
- **Safeguards:** a leakage test, pick tiers by out-of-sample edge size, best line across books, and closing-line-value tracking.
- **Ablation:** the project's own sheet stats and against-the-spread records were tested as extra inputs and dropped because they did not improve out-of-sample results.

## Technical stack

Python 3, about 12,300 lines across 10 core scripts plus 8 stand-alone research and backtest scripts. Data lives in flat CSV, gzipped CSV and JSON files (no database).

| Package | Used for |
|---|---|
| nflreadpy | Loads nflverse data: play-by-play, schedules and lines, team and player stats, injuries, snap counts, Next Gen Stats |
| pandas | DataFrames, groupby and merge, rolling and exponentially weighted averages, gzipped-CSV caches |
| NumPy | Least-squares and ridge fits, a from-scratch neural network (backprop, Adam), standardization, simulation |
| scikit-learn (optional) | `HistGradientBoostingRegressor`, the third model in the Spread AI ensemble |
| reportlab | Builds every PDF: tables, styles, conditional cell shading |
| requests | HTTP calls to The Odds API for live lines |
| streamlit, curl_cffi (optional) | A live dashboard and live in-game monitor, separate from the weekly run |

Standard library: argparse, json, pathlib, subprocess, importlib, re, datetime, tempfile, urllib, time.

**Skills shown:** feature engineering, ridge/OLS/neural-net/boosting models, walk-forward validation, leakage testing, ablation studies, confidence intervals and significance testing, calibration, closing-line-value evaluation, idempotent data pipelines with versioned caches, programmatic PDF reporting, and synthetic-data testing (a league with a known edge and one with none).

## Results, stated honestly

| Test | Result |
|---|---|
| Spread AI, walk-forward 2018 to 2026 (about 2,200 games never seen in training) | About 51.5% against the spread (95% interval about 49.4% to 53.6%) vs a 52.38% break-even. No pick tier met the project's own VALIDATED bar (54% or better on 100+ games and p < 0.10). |
| Margin model, straight-up | About 65% in-sample on roughly 1,200 games; log-loss 0.63 vs 0.69 for a coin flip. A small early-season check on logged picks was below 50%. |

> **What this means:** the market is efficient, and the model did not find a statistically confirmed edge against it. The value of the project is the pipeline, the leakage-free evaluation and the honest reporting of a negative result. Picks are unproven leans and **not betting advice**. The teal gap flags on the delta sheet were set from a few weeks of games and are exploratory.

## Setup and usage

```bash
pip install -r requirements.txt
python3 nfl_run_all.py                # data pull, all sheets, Spread AI, scorecard
python3 nfl_run_all.py --no-pull      # rebuild PDFs from the data already on disk
python3 nfl_run_all.py --spread-only  # only the Spread AI picks
python3 nfl_run_all.py --check        # check everything is in place
```

Reports are written to `generated/`. For live betting lines, set an `ODDS_API_KEY` environment variable (a free [The Odds API](https://the-odds-api.com) key) or put it in `novig_config.json`. **Never commit a real key.** Without a key the Spread AI falls back to nflverse's own spread.
